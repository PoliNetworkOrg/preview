Add Storage

Core Concepts

Many applications and services need a physical volume or storage to store their data or configuration.
On K3s, volumes are plain directories on the node's data disks, created on demand by the local-path provisioner when a PVC asks for one. We replaced Longhorn and the Azure Managed Disk volumes we used on AKS with it.

There are two storage classes, one per data disk:

Storage classDiskPath on the nodeUse it for
fastPremium SSD v2, 64 GB/srv/fast/volumes/<namespace>/<pvc>/Latency-sensitive databases (today: PostgreSQL and the Redis instances)
standard (default)Standard SSD, 128 GB/srv/standard/volumes/<namespace>/<pvc>/Everything else (today: InfluxDB, Prometheus, Grafana, Uptime Kuma)
  • The size is not enforced. storage: 4Gi in a PVC is a label, not a quota: a volume can grow until the whole disk is full, and then every app on that disk breaks. Check the free space first, and keep an eye on the PersistentVolumeHigh and NodeDiskHigh alerts.
  • ReadWriteOnce doesn't mean one pod. It limits a volume to one node, and we only have one node: two pods can mount the same volume and write to it at the same time. Make sure only one pod at a time uses it (see Recreate below).
  • Volumes are retained. Deleting a PVC doesn't delete its directory (reclaimPolicy: Retain).

Add a volume

First of all, SSH into the node and check how much space is available on the disk you want to use:

Once you verified you have sufficient space available, add the PVC to the app manifest:

Parameters:

  • namespace k8s namespace (set by the app's kustomization.yaml)
  • name should identify the app where the volume will be used
  • storage-class fast or standard (see the table above)
  • size expected size of the volume. Check resource units. e.g. 300M, 1Gi, 200Mi

Both are required

  • The kustomize.toolkit.fluxcd.io/prune: disabled annotation keeps Flux from deleting the PVC if it disappears from Git (e.g. a bad refactor). CI rejects PVCs without it.
  • The Recreate strategy avoids two pods writing to the same volume during a rollout.

The volume is created when the first pod using it is scheduled, so the PVC stays Pending until then: that's expected.

File permissions

local-path directories are owned by root. If your container runs as a non-root user, set securityContext.fsGroup on the pod to the user's group (see apps/redis for an example).

Back it up

Volumes are not backed up automatically. The application backup on the node only includes the databases and directories it knows about. If the new volume holds data we can't afford to lose, add it to the backup script: see Backups.
